# Лабораторная работа № 2
## Разработка файловой базы данных

**Дисциплина:** Управление данными
**Технологии:** C++17, Qt 6 Widgets, CMake

---

## 1. Цель работы

Разработать файловую базу данных с графическим пользовательским интерфейсом, обеспечивающую хранение, добавление, удаление, редактирование и поиск записей.

В рамках работы необходимо реализовать эффективные алгоритмы доступа к данным с использованием хеш-индекса и B+ дерева, а также обеспечить резервное копирование и восстановление базы данных.

## 2. Описание предметной области

В качестве предметной области выбрана библиотечная система.

База данных предназначена для хранения информации о книгах и управления библиотечной коллекцией: добавления новых книг, редактирования существующих записей, удаления книг и поиска по различным параметрам.

Каждая запись содержит следующие поля:

| Поле | Тип данных | Назначение |
|---|---|---|
| ID | int | Уникальный идентификатор книги, первичный ключ |
| Title | char[100] | Название книги |
| Author | char[100] | Автор книги |
| Year | int | Год издания |
| Genre | char[50] | Жанр книги |
| Pages | int | Количество страниц |
| isDeleted | bool | Признак логического удаления |

## 3. Организация хранения данных

База данных реализована на языке C++ с использованием файлового хранения. Записи сохраняются в бинарном файле. Каждая запись имеет фиксированный размер, что позволяет обращаться к ней непосредственно по смещению в файле.

Для работы с данными не требуется загружать всю базу в оперативную память. При необходимости отображения записей они считываются из исходного файла. Для ускорения поиска используются дополнительные индексные файлы.

В проекте реализованы два механизма индексирования:

- **Хеш-индекс** — для поиска записей по уникальному идентификатору.
- **B+ дерево** — для поиска записей по автору.

## 4. Реализация хеш-индекса

Хеш-индекс используется для быстрого поиска книг по уникальному идентификатору. В качестве ключа используется ID книги, а значение индекса содержит смещение соответствующей записи в бинарном файле.

Для разрешения коллизий применяется метод открытой адресации с линейным пробированием.

Реализованы следующие возможности:

- проверка уникальности ключей;
- обработка удалённых элементов с использованием специальных отметок;
- увеличение размера таблицы при достижении пороговой загрузки;
- сохранение индекса в отдельном файле;
- восстановление индекса при повторном открытии базы данных.

Средняя временная сложность поиска и добавления составляет O(1). В неблагоприятных условиях худшая сложность может достигать O(n).

## 5. Реализация B+ дерева

B+ дерево используется для индексирования записей по автору. Структура дерева позволяет эффективно выполнять поиск по ключу и хранить данные в упорядоченном виде.

Внутренние узлы содержат ключи и ссылки на дочерние узлы, а листовые узлы хранят ключи и соответствующие идентификаторы записей. Листовые узлы связаны между собой, что позволяет эффективно обходить найденные значения.

В проекте реализованы:

- вставка новых ключей;
- разделение узлов при переполнении;
- создание нового корня;
- поиск по автору;
- сохранение структуры индекса в файле;
- повторное открытие индекса.

Поиск в B+ дереве имеет временную сложность O(log n) по числу индексных ключей. При получении всех совпадений дополнительно учитывается количество результатов.

## 6. Графический пользовательский интерфейс

Для взаимодействия с базой данных разработан графический интерфейс с использованием библиотеки Qt 6 Widgets. Интерфейс позволяет выполнять основные операции без непосредственного взаимодействия с файлами базы данных.

Реализованы следующие возможности:

- создание и открытие базы данных;
- закрытие базы данных;
- отображение списка книг в таблице;
- добавление новых записей;
- редактирование существующих записей;
- удаление выбранных записей;
- поиск книг по ID, автору и названию;
- отображение полной таблицы после поиска;
- создание резервных копий;
- восстановление базы данных из резервной копии.

Поиск по названию и автору в графическом интерфейсе поддерживает частичные совпадения и не зависит от регистра символов.

## 7. Основные операции и их сложность

| Операция | Используемый алгоритм | Средняя временная сложность |
|---|---|---|
| Поиск по ID | Хеш-индекс | O(1) |
| Добавление записи | Хеш-индекс и B+ дерево | O(log n) |
| Поиск по автору | B+ дерево | O(log n + k) |
| Поиск по названию | Линейный просмотр записей | O(n) |
| Удаление записи по ID | Хеш-индекс и логическое удаление | O(1) |

Здесь n — количество записей в базе данных, k — количество найденных совпадений.

При оценке сложности учитывается работа индексных структур. Дополнительные операции чтения и записи файлов также влияют на фактическое время выполнения.

## 8. Резервное копирование и восстановление

В программе предусмотрена возможность создания резервных копий базы данных и связанных с ней индексных файлов.

Восстановление позволяет вернуть базу данных к состоянию, сохранённому в резервной копии.
